# Verification record: 0.3.0 (agent harnesses)

What was run, for real, before 0.3.0 was proposed for release, and what
was observed. The primary goal was confirming that the default Claude
Code path is unchanged by the harness layer
([PR #184](https://github.com/Stephenson-Software/gardener/pull/184)).
The `command` harness was a secondary goal.

- **Code verified:** commit `447823a`. The only later change is the
  version bump (`0.2.0` → `0.3.0`) and this record.
- **Date:** 2026-10-10.
- **Environment:** WSL2 (Linux 5.10), Python 3.11.15, Claude Code CLI
  2.1.293, Ollama with `llama3.2:3b`.
- **Target repo:** the public `Stephenson-Software/multiplyTwoNumbers`. It
  is already in the operator's garden, so the nightly run tends it anyway.
- **Isolation:** every run below set `GARDENER_STATE_DIR` and
  `GARDENER_CACHE_DIR` to a fresh scratch directory and
  `GARDENER_USAGE_REPORTING_ENABLED=false`, with `GARDENER_HUB_URL` unset.
  So no run reached the operator's real run history, Discord alerts, hub
  or usage reporting. The isolated state directory also meant an empty
  merge allow-list.
- **Conventions repo:** the operator's own, which is private and not
  named here.

## 3. Claude Code path driven by the new settings

The settings were in the isolated `notify.env`, not the environment, to
exercise the file fallback:

```
GARDENER_CLAUDE_BIN=/root/.local/bin/claude
GARDENER_HARNESS_MODEL=claude-sonnet-5-5
GARDENER_ALIGN_TIMEOUT=1200
```

The run used `PATH=/usr/bin:/bin`, so `claude` was **not** on `PATH`;
only `GARDENER_CLAUDE_BIN` could find it.

| Check | Observed |
|---|---|
| Exit code | `0`; 34.6 s, $0.21, 0 denials, `GARDENER_SUMMARY:` present |
| Binary | found via `GARDENER_CLAUDE_BIN` with `claude` off `PATH` |
| Model | every assistant turn in the transcript reports `claude-sonnet-5-5`, the setting, not the CLI default |
| Tools used | `Read` ×14, `Glob` ×1 |
| Cached clone and GitHub | `git status --porcelain` empty; HEAD `f85853a`; `pushedAt` unchanged |

## 5. `command` harness (secondary goal)

The bundled `examples/harnesses/ollama_report_agent.py` against local
Ollama `llama3.2:3b`, configured entirely from `notify.env`
(`GARDENER_HARNESS=command`, `GARDENER_HARNESS_COMMAND`,
`GARDENER_HARNESS_MODEL`, `GARDENER_ALIGN_TIMEOUT`,
`GARDENER_HARNESS_ALLOW_UNSCOPED=file-issue`), plus
`OLLAMA_NUM_CTX=8192`. Run on the release tree, with the version already
bumped to 0.3.0.

| Check | Observed |
|---|---|
| `align` (report) | exit 0 in 41.7 s, `ok=True`, `GARDENER_SUMMARY:` present, run recorded with session id `ollama:llama3.2:3b`; clone `git status --porcelain` empty, `pushedAt` unchanged |
| `tend` with only `file-issue` opted in | refused: "refusing tend mode on the `command` harness … Add tend to GARDENER_HARNESS_ALLOW_UNSCOPED" |
| `overnight` with only `file-issue` opted in | refused at pre-flight, before any repo was dispatched |
| Unreachable `OLLAMA_HOST` | `ok=False, blocked=True` (the example's `"blocked": true`) |
| `GARDENER_ALIGN_TIMEOUT=soon` | setup error before any clone or dispatch |
| `doctor --offline` | no problems; checked the configured command instead of `claude` |

The quality of a 3B model's checklist is not part of this record. These
runs show the plumbing works, not that a small local model produces a
useful audit.
