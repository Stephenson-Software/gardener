# Verification record: 0.4.2 (signals reach running agents)

What was run, for real, before 0.4.2 was proposed for release.

0.4.1 started running each agent in its own session, so a timeout could
kill the agent's whole process tree. One side effect: signals that used to
reach the agent along with gardener no longer did.
- A terminal's **Ctrl-C** goes to the foreground process group, which the
  agent has left. On the main thread gardener's KeyboardInterrupt still
  killed it. On `overnight --concurrency` worker threads nothing did, so
  the agents kept running.
- A **SIGTERM or SIGHUP to gardener alone** never reached the agent. That
  was also true before 0.4.1, when it was simply never handled.

0.4.2 tracks the process group of every running agent. While a dispatching
command runs, it installs handlers for SIGINT, SIGTERM and SIGHUP that kill
every tracked group. Gardener then reacts to the signal as it did before:
a KeyboardInterrupt for SIGINT, the default termination for the others. A
signal gardener was started ignoring (SIGHUP under `nohup`, as a scheduled
job may run it) stays ignored and kills nothing. `gardener stop`/`kill`
already signalled the whole process tree and are unchanged.

- **Code verified:** branch `fix/signal-kills-agent-groups`.
- **Date:** 2026-10-11.
- **Environment:** WSL2 (Linux 5.10), Python 3.11.15 and 3.10.20.

## Automated tests

`TestAgentSignalGuard` (unit) uses real processes, never `claude`. A driver
runs two agents on worker threads, as `overnight --concurrency 2` does, and
each agent starts a child and sleeps.

| Test | Asserts |
|---|---|
| SIGTERM | The driver dies by SIGTERM; both agents' children are gone |
| SIGINT | The driver stops; both agents' children are gone |
| SIGHUP | The driver dies by SIGHUP; both agents' children are gone |
| Ignored SIGHUP | The driver keeps running and the agents survive; a later SIGTERM still cleans up |
| Handlers restored | The previous handlers are back after the guard |
| Off the main thread | The guard changes nothing |
| Finished agents | A finished agent is no longer tracked |

With the guard disabled, the SIGTERM, SIGINT, SIGHUP and ignored-SIGHUP
cleanup tests fail. The offline integration test
`test_signals_to_gardener_kill_the_agent` sends SIGTERM and SIGINT to a real
`gardener align` whose stand-in agent sleeps, and checks the agent's child
is gone. With the guard removed from the CLI, the SIGTERM case fails.

The full unit suite and the offline integration tier pass on Python 3.11
and 3.10. As in 0.4.1, the unit suite was run with a booby-trapped `claude`
first on `PATH`, and it was never invoked.

## Real runs

The guard changes only what happens when gardener receives a signal, not
how an agent is started or how its result is read. A real Claude Code
report `align` was still run on this branch, through the integration
suite's Claude Code tier, to confirm a normal dispatch is unaffected:
exit 0 in 26 s for $0.15, "6 gap(s) found across 4 section(s)", clone
unchanged.

The unit suite now has 1,119 tests.
