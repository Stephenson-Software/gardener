# Verification record: 0.4.3 (session control, whole-line logs, lifecycle tests)

What was run, for real, before 0.4.3 was proposed for release. The
integration suite was extended past `align` to the rest of a dispatch's
life: `tend`, `overnight`, and `ps`/`stop`/`kill`. Three bugs turned up and
are fixed here.

- **Code verified:** branch `feature/integration-lifecycle`.
- **Date:** 2026-10-11.
- **Environment:** WSL2 (Linux 5.10), Python 3.11.15 and 3.10.20, git
  2.25.1.

## Bugs found and fixed

1. **`gardener kill` reported success as failure.** It checked the session
   the instant after sending the signal, before the process had exited.
   Even with an ordinary shell as the session's parent, `gardener kill`
   exited 1 with "still running after being signalled", while `gardener ps`
   a moment later showed the session gone. `kill` now waits up to 2
   seconds (`KILL_SETTLE_SECONDS`) for the session to exit; it still never
   escalates.
2. **A zombie counted as alive.** `pid_alive` used `os.kill(pid, 0)`, which
   succeeds on a process that has exited but not yet been reaped by its
   parent. `gardener stop` against such a session waited out its grace
   period, escalated to SIGKILL, and still reported it as stuck. A zombie
   (`Z` in `/proc/<pid>/stat`) is now treated as gone.
3. **Concurrent `overnight` dispatches glued run-log lines together.**
   `print` writes its text and its newline separately, so two worker
   threads interleaved mid-line. Seen in a real `--concurrency 2` log:
   `...cache/repos/it-fixture__secondgardener: it-fixture/multiply checked
   out at ...`. The dashboard reads these logs line by line, so a glued
   `finished tending` line can leave a repo looking stuck. The stderr tee
   now writes whole lines only, under a lock, keeping each thread's
   unfinished line until its newline arrives or it is flushed.

## Automated tests

New offline integration file `integration/test_offline_lifecycle.py`, run
through the real CLI:

| Area | Tests |
|---|---|
| Sessions | `ps` lists a running `align`; `stop` and `kill` end it and its agent |
| Cloning | a second `align` refreshes the clone the first made, through `gh` |
| `tend` | refused without the unscoped opt-in; `merge_allowed` only with `--allow-merge` and the allow-list; a missing dev-loop skill is bootstrapped inside the sandbox HOME |
| `overnight` | `--concurrency 2` tends every garden repo with no glued log lines; an unready harness aborts before any dispatch; Ctrl-C mid-batch kills every agent |

It runs against a local stand-in for GitHub (`integration/fake_gh.py`),
which serves clones from local bare repositories and logs every call. Each
test asserts that nothing beyond read-only `gh` calls was made. HOME points
into the sandbox, and no file was written to the operator's real
`~/local-skills` or `~/.claude/commands`.

New unit tests:
- `TestKillSettle`: `kill` waits for the session to exit, and never
  escalates.
- `TestPidAlive`: a real unreaped child reads as not alive, and the state
  field is parsed after a command name containing `)`.
- `TestTeeStreamDirectly`:
  - a line is written whole only when its newline arrives;
  - `flush` writes out an unfinished line;
  - four threads printing 300 lines each never glue a line;
  - `tee_stderr` still logs an unfinished last line.

Each fix was reverted in turn, and the matching tests failed:

| Reverted | Failed |
|---|---|
| `sessions.py` | `test_stop_ends_the_session_and_its_agent`, `test_kill_ends_the_session_and_its_agent` |
| `run_log.py` | the concurrent-print unit test, and the `overnight` test's glued-line check in 3 of 3 runs |
| 0.4.2's signal guard | the Ctrl-C `overnight` test: two agents survived and `overnight` did not exit |

Full results:
- Unit suite and both offline integration files pass on Python 3.11 and
  3.10.
- The integration run was 46 tests, with 13 live tests skipped.
- The unit suite was run with a booby-trapped `claude` first on `PATH`,
  which was never invoked.
- No stand-in agent was left running afterwards.

## Real run

A real Claude Code report `align` on this branch, through the integration
suite's Claude Code tier, confirmed that the whole-line tee changes nothing
for a normal run: exit 0 in 31 s for $0.16, the clone unchanged, and its run
log 10 whole lines, none glued. The unit suite now has 1,128 tests.

## Not changed

No dispatch logic changed: what an agent is given, how it is started, and
how its result is read are as in 0.4.2. The `kill` wait applies only after
the signal has been sent.
