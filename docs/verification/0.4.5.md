# Verification record: 0.4.5 (first real write-mode runs, conventions kept private)

`align --implement` and `align --file-issue` were run for real for the
first time. They worked, but showed that `--implement` posts the conventions
repo's location, and 0.4.5 fixes that.

- **Code verified:** branch `feature/live-write-modes`.
- **Date:** 2026-10-11.
- **Environment:** WSL2 (Linux 5.10), Python 3.11.15 and 3.10.20, git
  2.25.1, Claude Code with the operator's subscription.
- **Target:** a private throwaway repository holding the integration
  fixture's `multiply` tool. **Conventions:** the bundled fixture.

## The finding

The `--implement` prompt told the run to cite "the conventions doc(s) by
URL" in its pull request. Neither write-mode prompt said to keep the
conventions repo out of what it posts. The first real `--implement` pull
request opened with "audited against the engineering conventions at
file:///tmp/…/conventions-src".

A conventions repo can be private while the repos it audits are public. In
an operator's own fleet, issues opened by `--file-issue` on 2026-08-08 had
put a private conventions repo's name in their titles, in four public
repositories. Later `tend` runs quoted those titles in about 15 public pull
requests. Cleaning those up is the operator's call; this release stops new
ones.

**Fix:** both write-mode prompts now carry
`CONVENTIONS_PRIVACY_REQUIREMENT`. It says never to name the conventions
repo, or give its URL or local path, in a branch name, commit message, pull
request or issue, and to cite its documents by file name only.
`--implement` now asks for the docs "by file name".

## Real runs

| Run | Prompt | Result | Cost | Time |
|---|---|---|---|---|
| `--file-issue` | old | one issue with a checklist of gaps, citing docs by file name | $0.29 | 70 s |
| `--implement` | old | one open, unmerged PR, 6 files, from `feature/align-with-conventions`; **body named the conventions path** | $0.26 | 67 s |
| `--file-issue` | new | one issue; no conventions URL or name | $0.31 | 71 s |
| `--implement` | new | one open, unmerged PR, 6 files; no conventions URL or name ("aligned with the engineering conventions … per `docs/README_STRUCTURE.md`") | $0.31 | 77 s |

In every run:
- **No merge:** the `--implement` mode's `Bash(gh pr *)` allow-pattern
  would permit `gh pr merge`; the prompt held.
- **The default branch never moved.**
- **Each run opened exactly one PR or one issue, and nothing else.**
- **`--file-issue` left the clone unchanged.**
- **Every post was in passive voice, with the Gardener-session line and the
  sign-off.**

The PRs and issues were closed afterwards, the PR branches deleted.

## Tests

- **Unit** (`tests/test_cli.py`): both write-mode prompts include
  `CONVENTIONS_PRIVACY_REQUIREMENT` and no longer say "by URL". Without
  the fix the test cannot even import the constant.
- **Live tier** (`integration/test_live_write_modes.py`, new): the two
  runs above, as tests. They need `GARDENER_IT_CLAUDE=1` and
  `GARDENER_IT_WRITE_REPO`. Beyond the outcome checks, the conventions URL
  and directory name must not appear in a title, body, branch name or
  commit message. The old prompt's PR would fail that check; its body
  contained the path.
- **Full suites:** unit and integration pass on Python 3.11 and 3.10.
  Integration has 74 tests, 17 of them live and skipped.
